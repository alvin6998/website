# CGNAT（Carrier-grade NAT）電信級 NAT / 營運商級 NAT

## 一、什麼是 CGNAT

網際網路供應商（ISP）提供一個公共IP給多個用戶

**一般NAT**
```
用戶 →（私有IP）→ 路由器NAT → （公網IP） → 網際網路
```

**經過CGNAT**
```
用戶 →（私有IP）→ 路由器NAT → （電信級私有IP） → CGNAT →（公網IP） → 網際網路
```

也就是說，你拿到的「對外 IP」其實根本不是公網 IP，而是電信商內部又劃了一層私有網段。

CGNAT用的IP通常是 `100.64.0.0/10`，即 100.64.0.0 到 100.127.255.255

## 二、為什麼會有 CGNAT

- **IPv4 位址枯竭**：全球 IPv4 早就分配完了（RIPE NCC 2019年11月正式分配完最後一個IPv4位址池），電信商手上的公網 IP 數量遠少於用戶數
- 由於用戶的裝置不直接存在於公網上，可能在一定程度上有助於保護用戶免受攻擊

## 三、CGNAT的缺點

1. **無法進行埠轉發** – 沒有公網IP
2. **無法執行網路代管服務** – 第一個的延伸結果
3. **CGNAT使執法行動變得困難，需要NAT紀錄檔** – 因為多人共用同一IP，要查額外紀錄「IP + Port + 時間戳 + 連線細節」才能對應到個別用戶（嘿，燈下黑！）
4. **使用IP封鎖的網站，可能會讓同IP下的用戶遭受牽連** – 哈，畢竟出門戴著的是NAT出口的公網IP，別人要連的時候才發現被封鎖了
5. **P2P / NAT穿透成功率下降** – 多個NAT轉換，讓STUN 打洞更容易失敗，遊戲連線、視訊通話品質可能受影響

## 四、如何不用CGNAT

1. **申請公網IP**（可能需要額外付費）
2. **使用VPN或VPS當中繼** – 租一台有公網的VPS，透過VPN把家裡的服務轉出去，本質是借用VPS的公網IP
3. **使用支援IPv6的電信商** – IPv6位址空間超大，通常不需要NAT轉換，如果目的服務支援IPv6，那麼就能直接對外

## 五、也有不用CGNAT的網段

標準做法應該用 `100.64.0.0/10`（CGNAT專用網段，在RFC 6598有定義），就是為了避免跟用戶的RFC 1918 網段（10.x / 172.16.x / 192.168.x）衝突

但是呢有些電信商為了省事，直接用RFC 1918 的私有IP 10.x.x.x 來當做CGNAT網段

**這在企業會有甚麼影響？**

雖然一般用戶不會察覺，但企業有內部VPN或需要點對點的服務要連線，會因為路由衝突而連不上
