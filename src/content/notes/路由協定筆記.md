在開始 RIP、OSPF、BGP 之前要先了解什麼是 IGP、EGP、AS。

## AS（Autonomous System，自治系統）

- 網際網路是由無數個 AS 組成的
- 每個 AS 皆為一個獨立網路(一個獨立的城堡)
- 為了方便管理,AS 都有一個全球唯一編號叫 ASN(Autonomous System Number)
- 舉例:中華電信 ASN 為 AS3462、台灣大哥大 ASN 為 AS24158、遠傳電信 ASN 為 AS9674
- 當然,一個電信商可以持有多個 ASN

## IGP（Interior Gateway Protocol，內部閘道協定）

- **用途**:管理 AS 內部的路由(管理城堡內的道路)
- **目標**:找出最佳/最短路徑
- **協定類型**:RIP;OSPF
- 舉例:一個城堡內有 20 個住戶,彼此要互通,就進行了內部道路規劃

## EGP（Exterior Gateway Protocol，外部閘道協定）

- **用途**:管理 AS 之間的路由(管理不同城堡之間的道路)
- **目標**:著重於商業、政策考量與穩定性
- **協定類型**:BGP
- 舉例:城堡之間為了運送物資,就建立了聯外道路規劃

## 進入正題

## RIP（Routing Information Protocol，路由資訊協定）

- **協定類型**:距離向量路由協定
- **傳輸協定**:UDP
- **更新週期**:每隔 30 秒會與相鄰的路由器交換訊息

### 特點
1. 設定簡單,適合小型網路
2. 收斂速度慢,易發生路由迴圈
3. 規模限制在 15 跳(hop)內,超過視為不可達
4. 只看跳數,不考慮實際線路品質

### 運作邏輯
1. 每台路由器只知道鄰居回報的「距離」,不知道完整拓樸
2. 定期把自己完整的路由表傳給所有鄰居
3. 收到後比對,若有更短路徑則更新自己的路由表
4. 反覆迭代直到收斂

**版本**:RIPv1(無 CIDR 支援)、RIPv2(支援 VLSM/CIDR,含協定認證機制)

---

## OSPF（Open Shortest Path First，開放式最短路徑優先）

- **協定類型**:鏈路狀態路由協定
- **傳輸協定**:無,直接承載在 IP 協定之上
- **更新週期**:僅在變化時

### 特點
1. 收斂速度快、效率高
2. 支援分層設計與多維度成本度量
3. 使用 Dijkstra 最短路徑演算法
4. 適合大型企業與 ISP 網路
5. 能反映實際線路品質

### 運作邏輯
1. 每台路由器透過 Hello 封包發現鄰居,建立鄰接關係(Adjacency)
2. 路由器互相交換 LSA(Link State Advertisement),描述自己與鄰居的連線狀態
3. 所有路由器最終擁有相同的 LSDB(Link State Database),即完整拓樸圖
4. 各自以自己為根,執行 Dijkstra 演算法,計算出最短路徑樹(SPF Tree)
5. 依此樹產生自己的路由表

---

## BGP（Border Gateway Protocol，邊界閘道器協定）

- **協定類型**:向量性協定或基於策略導向的路由
- **傳輸協定**:TCP 179 埠
- **更新週期**:預設為 60 秒,採用增量更新

### 模式
- **eBGP**:不同 AS 之間(外交部)
- **iBGP**:同一 AS 內部路由器之間同步外部 eBGP 路由資訊(內政部)

### 特點
- 不追求最佳(最短)路徑,而是「符合商業/政策考量」的路徑
- 可高度客製化路由策略
- 收斂相對較慢,但可控性與可擴充性極強
- 支撐全球網際網路骨幹路由表(目前全球 BGP 路由表已超過 90 萬條)

BGP 有一個致命問題,組態錯誤會導致網際網路流量紊亂甚至中斷。
例如:AS7007 事件、2021 年 Facebook 當機事件、BGP 劫持

### 運作邏輯
- 路由器之間建立 TCP 連線後交換路由資訊
- 每條路由帶有完整的 AS_PATH(所經過的 AS 清單),而非單純距離
- 路由選擇不是找「最短路徑」,而是根據一系列路徑屬性(Path Attributes)做政策性決策,常見屬性包括:
  - **AS_PATH**:經過的 AS 清單,長度也是選路依據之一
  - **LOCAL_PREF**:AS 內部優先度設定
  - **MED**(Multi-Exit Discriminator):建議鄰居 AS 走哪個出口
  - **Origin**:路由來源類型
  - **Next_Hop**:下一跳位址

# AS7007 事件

### 起因
美國維吉尼亞州麥克萊恩的公司 MAI 網絡服務(MAI Network Services)內部一台編號 AS7007 的路由器發生軟體錯誤或設定錯誤。

### 路由外洩
該路由器意外向網際網路發布了大量詳細的 /24 網路前綴路由表,並將 AS 路徑強行重寫指向自己。

### 路由黑洞
全球許多骨幹路由器誤信這批更精確的 /24 路由(BGP 選路時,精確度優先於 AS 路徑長度),將大量原本要到其他地方的網路流量傳送給 AS7007。

### 骨幹癱瘓
大量流量被錯誤導向 AS7007,造成部分網路設備與連線嚴重過載,進而引發大規模網路中斷。

### 事情發生後
- 該路由器第一時間已被停用,但錯誤的路由仍持續在其他業者的路由表中擴散,導致各地路由器不斷當機、重開機、重新學習路由,形成惡性循環,直到骨幹業者主動關閉設備、加上過濾規則後才逐漸平息
- 促使各大網際網路服務供應商(ISP)改變 BGP 的操作與過濾規範(例如限制客戶只能宣告自己 AS 的網段、部分業者要求先在 RADB 登記網路資訊),以防止錯誤路由輕易擴散

# 2021 年 Facebook 當機事件

### 當機原因

資安專家將問題判定為邊界閘道器協定(BGP)復原了代管 Facebook 網域名稱系統(DNS)的 IP 位址前綴,讓使用者無法解析、存取 Facebook 和相關域名。效果在全世界明顯可見;瑞士網際網路服務提供商 Init7 記錄顯示,Facebook 在邊界閘道器協定更改後伺服器的流量大幅下降。

![2021年10月4日全球當機期間 Facebook 服務的流量](/notes/routing/fb-outage-traffic.png)
*圖 1:2021 年 10 月 4 日全球當機期間 Facebook 服務的流量。*

Cloudflare 報告稱,在 15:39 當下,Facebook 進行了大量 BGP 更新,所有的權威域伺服器集體撤回 IP 前綴的轉發,使得 Facebook 的 DNS 伺服器無法從網際網路存取。到了 15:50,Facebook 的域名已從所有主要公共解析器的快取中過期。21:00 稍早時,Facebook 恢復宣布 BGP 更新。21:05,Facebook 的域名再次可以解析。

![公共域名解析服務回傳 SERVFAIL 狀態](/notes/routing/fb-outage-servfail.png)
*圖 2:公共域名解析服務為 Facebook.com 回傳「SERVFAIL」狀態,意指伺服器錯誤。*

10 月 5 日,Facebook 的工程團隊在部落格發表一篇文章,解釋此次當機的原因。在例行維護期間,他們運行一條命令來評估全球骨幹網的容量,但該命令意外地切斷了 Facebook 骨幹網中的所有連接,使 Facebook 資料中心從網際網路斷開。雖然 Facebook 的 DNS 伺服器在獨立的網路上運行,但它們的設計目的是在無法連接到資料中心的情況時撤回其 BGP 轉發,從而使網際網路無法連線到 Facebook。

在一批工程團隊前往加利福尼亞州聖塔克拉拉資料中心重設伺服器電腦後,Facebook 逐漸回復正常。到 22:45 左右,Facebook 及相關服務均回到能自由連線的狀態。

### 影響

![當機期間 Facebook 畫面](/notes/routing/fb-outage-screen.png)
*圖 3:當機期間 Facebook 畫面*

此次當機切斷了 Facebook 公司的內部通訊,讓員工無法寄送或接收外部電子郵件、存取公司目錄以及對 Google 文件和 Zoom 等服務進行身分驗證。《紐約時報》報導稱,員工無法使用安全識別證進出大樓和會議室。追蹤網路當機的站點 Downdetector 在當天收到超過 1000 萬份問題報告,成為迄今為止收到數量最多的一次。安全檢查員史蒂夫·吉布森(Steve Gibson)表示,例行 BGP 更新出錯將會修復錯誤且擁有遠端存取權限的人擋在伺服器外,而能在機房物理接觸設備的人也無權限修復錯誤。

Google Public DNS 服務因當機影響而變慢,Gmail、TikTok 和 Snapchat 的使用者也表示有變慢體驗。CNBC 報導稱,此次當機是 Facebook 自 2008 年以來經歷過最糟糕的一次。當機當天,該公司股價下跌近 5%,市值蒸發約 473 億美元,連帶使 Facebook 執行長馬克·祖克柏的個人財產縮水逾 60 億美元。根據《財星》雜誌和 Snopes 的一份報告稱,Facebook 至少損失了 6000 萬美元的廣告收入。

當機對仰賴 Facebook 的「Free Basics」計劃的開發中國家人民產生重大影響,波及通訊、商業和人道主義工作。
